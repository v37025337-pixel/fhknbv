# Адаптивное обучение 0.3.0

Цель этого цикла — улучшить модель мира по проверяемым ошибкам прогноза. Исходный арбитр механизмов мог успешно синтезироваться, но само его наличие не доказывало улучшения поведения. Новый цикл выбирает временную модель, которая используется и для ближайшего прогноза, и в поиске плана.

## Как ядро выбирает модель

Базовый прогноз DIGITAL_MIND с проверяемой поправкой L0 сохраняется. Рядом обучаются две модели с той же системой нелинейных признаков, но разными коэффициентами забывания RLS: `recent = 0.98`, `stable = 0.999`; базовый коэффициент — `0.994`.

На каждом реально наблюдённом переходе ядро сначала фиксирует прогнозы всех моделей, затем получает результат, измеряет их ошибки и только после этого обучает параметры. Выбор следующего прогноза использует предыдущие ошибки. Вызовы прогнозов во время поиска плана не пополняют свидетельства и не обучают модели.

Для допуска альтернативы нужны 64 таких прогноза. По последним 64 разностям ошибок базовой модели и кандидата считаются четыре средних блока по 16 наблюдений. Среднее блоков минус две стандартные ошибки должно быть положительным; средний выигрыш на последних восьми наблюдениях тоже должен быть положительным. Это консервативная эвристика допуска, а не статистическое доказательство будущего выигрыша. При исчезновении этих условий ядро возвращается к базовой модели или выбирает другую допущенную альтернативу.

Семейство альтернатив и правило допуска задаёт разработчик. Ядро обучает параметры и выбирает альтернативу по своему опыту; произвольные алгоритмы и новые физические законы эта версия не изобретает.

## Измерение

`tools/benchmark_learning.py` использует development-seeds `0, 1, 2` и заранее объявленные evaluation-seeds `10..15`. Коэффициенты и допуск не подбирались по оценочным результатам. Каждый запуск содержит 640 переходов; на переходе 320 искусственный мир меняет скрытые последствия действий.

Основное сравнение даёт обеим моделям одни и те же наблюдения и случайные действия. Прогноз измеряется до обучения на результате этого перехода. Поправка L0 в этом сравнении отключена у обеих моделей, чтобы изолировать новый выбор временной модели. Это один тип искусственного мира, а не оценка общего интеллекта.

| Оценочные миры, 6 запусков | Базовая MSE | Адаптивная MSE | Снижение |
| --- | ---: | ---: | ---: |
| Все 640 переходов | 0.01260805 | 0.01229907 | 2.45% |
| До смены режима | 0.01091968 | 0.01072777 | 1.76% |
| После смены режима | 0.01429642 | 0.01387037 | 2.98% |
| Последние 80 переходов | 0.00764829 | 0.00750900 | 1.82% |

Ошибка за весь запуск снизилась во всех шести оценочных мирах. На последних 80 переходах улучшились два мира, в четырёх результат совпал с базовым: альтернативе не обязательно сохранять управление. В development-запусках снижение общей ошибки составило 2.50%.

Полный отчёт: [examples/learning_benchmark.json](examples/learning_benchmark.json). При `--closed-loop` отдельно проверяются агенты, сами выбирающие действия, со включённым L0 и обычным планировщиком. Они посещают разные состояния: сравнение их MSE уже не является сравнением на одинаковом опыте. Награды публикуются отдельно по компонентам, без объявления роста интеллекта или универсального улучшения поведения.

В полном контуре на шести оценочных seed средняя MSE составила `0.00671209 → 0.00621358` (снижение 7.43%), но на seed 14 и 15 ошибка выросла. Средние четыре компонента награды изменились с `[-0.05583, -0.17325, -0.05768, -0.05106]` на `[-0.05652, -0.17373, -0.05630, -0.05604]`: улучшился один компонент, три ухудшились. Поэтому подтверждён выигрыш в прогнозировании на общем опыте; улучшение наград и достижение целей этим циклом не подтверждено. Параметры после оценочного сравнения не изменялись. Новый выбор модели остаётся экспериментальной опцией, включённой по умолчанию и отключаемой указанным ниже флагом.

## Запуск и восстановление

```bash
python -m digital_mind_core run --steps 640 --report report.json --checkpoint replay.json
python -m digital_mind_core run --steps 640 --no-adaptive-learning --report baseline.json
python tools/benchmark_learning.py --closed-loop --report examples/learning_benchmark.json
```

В Python прежнее поведение прогнозирования включается через `KernelConfig(adaptive_learning=False)`. Прогнозы, количество использований каждой модели, основания переключения и возвраты доступны в `report()['adaptive_learning']`. Текущая модель также передаётся в символическое состояние и консолидацию self-модели.

Replay восстанавливает обученные альтернативы и историю допуска; их параметры включены в контрольный хеш состояния. Это восстановление через повторение симуляции с теми же исходниками и численными библиотеками. Replay старых версий отклоняется из-за несовпадения исходного кода. Сохранённые JSON-механизмы переносятся отдельно; внешние логические задачи не входят в replay симуляции.

Для 96 переходов с `adaptive_learning=False` отдельно проверено совпадение прогнозных метрик, наград и хеша скрытого состояния мира с исходным ядром `d478397`. Проверки дополнительно покрывают отсутствие использования текущего результата в текущем прогнозе для всех трёх ветвей, отзыв допуска, отсутствие обучения при планировании и продолжение после replay.

Это шаг к более самостоятельному обучению вычислительного агента. Наличие цифрового сознания, общего разума или неограниченного самоизменения этими опытами не установлено.
