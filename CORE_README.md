# DIGITAL_MIND Unified Core 0.2

Экспериментальное ядро объединяет DIGITAL_MIND v0.7, адаптированный канонический L0 и ветку v0.28 mechanism genesis. Все три компонента участвуют в одном цикле. Исходные загрузки и предыдущая сборка v0.1 сохранены отдельно.

Это работающий исследовательский прототип: прогнозирование искусственного мира, вопросы по ошибкам, память, планирование, символические выводы и ограниченный синтез программ. Проверки ниже подтверждают работу этих механизмов; они не устанавливают наличие сознания или общего интеллекта.

## Запуск

Нужны Python 3.10+, NumPy и SciPy. Из каталога проекта:

```bash
python -m pip install -r requirements.txt
python -m digital_mind_core run --steps 640 --seed 0 \
  --report report.json --checkpoint replay.json --save-mechanisms mechanisms.json
python -m digital_mind_core run --resume replay.json --steps 128 --report continued.json
python -m digital_mind_core run --mechanisms mechanisms.json --seed 7 --steps 96
```

В `artifacts/` также находится проверенный wheel. Его можно установить через `python -m pip install artifacts/digital_mind_core-0.2.0-py3-none-any.whl`. После установки доступна команда `digital-mind`.

## Общий цикл

1. DIGITAL_MIND наблюдает мир, обновляет ансамбль прогнозов и хранит эпизоды.
2. Символическое ядро v0.28 получает события наблюдения и ошибки предыдущего прогноза, выводит необходимость пересмотра плана и обновляет операционную самооценку.
3. Исполнитель L0 ARC использует этот вывод вместе со своим расписанием и вызывает планировщик DIGITAL_MIND.
4. При пересмотре плана накапливаются пары прогнозируемых стоимостей: продолжение предыдущего действия и новый план.
5. После накопления отдельных обучающих, проверочных и отложенных примеров synthesis engine предлагает программный арбитр. Принятый механизм компилируется в L0 Control IR и участвует в последующих решениях.
6. Результат действия обновляет прогнозную модель, вопросы, память и самооценку для следующего шага.

Контрольная спецификация арбитра задана разработчиком: выбрать меньшую из двух прогнозируемых стоимостей. Это синтез локальной программы по примерам, а не самостоятельное открытие законов мира. Для автоматического синтеза используются первые 6 прошлых пар и их перестановки, следующие 4 пары для CEGIS и следующие 6 для отдельной отложенной проверки. Текущая будущая пара не входит в эти наборы. Поиск ограничен грамматикой, размером выражений и числом попыток.

Файл `digital_mind_core/kernel.py` содержит общий цикл; `cognition.py` — фасад символического ядра, регистрацию и хранение механизмов; `evolution.py` — накопление примеров и допуск арбитра; `executive.l0` — исполнитель ARC. В `legacy_v028/` сохранены совместимые модули, адаптеры данных и исходные тестовые скрипты. Старое переписывание целого исходного файла автоматически не запускается.

## Исправления

- Неудачный CEGIS-поиск больше не сообщает `FOUND` в итоговой сводке.
- Правила и результаты отделены от внутреннего состояния копированием; изменение возвращённого снимка не меняет действующее правило. Исправлено повторное связывание переменной со значением `None`.
- Генерируемый Python и интерпретатор выражений используют одинаковую числовую семантику, включая сравнение с допуском. Экспорт условной функции совместим с L0. Проверяются имена функций, аргументы и конечность чисел.
- Механизм допускается после независимой отложенной проверки. При нарушении контракта на последующем вызове арбитр отключается и решение возвращается к базовому планировщику.
- Механизмы сохраняются как JSON AST: проверяются операции, размеры, переменные, исходный хеш и сертификаты отложенной проверки. Загрузка проходит целиком до публикации механизмов; сохранённый Python не исполняется.
- Исправления v0.1 для коротких спектральных выборок, предсказания по замороженной L0-модели и проверяемого допуска её веса сохранены.
- Восстановление теперь учитывает начальные импортированные механизмы, состояние символического ядра и синтеза.

Числа в механизмах вычисляются как `float`; точная арифметика произвольно больших целых не поддерживается.

## API

```python
from digital_mind_core.kernel import KernelConfig, UnifiedMind

mind = UnifiedMind(KernelConfig(seed=0))
mind.run(96)
result = mind.process({
    "facts": [("p", "a")],
    "rules": [([("p", "$x")], ("q", "$x"))],
    "queries": [("q", "a")],
})
assert result["inferences"][0]["value"]
mind.save_mechanisms("mechanisms.json")
```

`mind.connect("dataset.csv")` использует адаптер v0.28 и добавляет факты схемы и числа строк в то же символическое состояние. Доступны запросы вида `("dataset_rows", "connection_1", 2)` и `("dataset_field", "connection_1", "Population", "int")`.

Для отдельного эксперимента с синтезом доступен `digital_mind_core.cognition.CognitiveCore`. Проверяемая спецификация, обучение и отложенные примеры передаются явно; примеры использования находятся в `tests/test_cognition.py`.

## Сохранение и восстановление

`--checkpoint` сохраняет проверяемый рецепт детерминированного повторения симуляции, а не мгновенный снимок всех объектов. Восстановление повторяет уже выполненные шаги и проверяет fingerprint состояния; его время растёт с длиной истории. Начиная с replay v3, source SHA и версии NumPy/SciPy сохраняются как provenance, но не являются жёстким запретом: checkpoint принимается только если текущий runtime детерминированно воспроизводит сохранённое состояние. Replay v2 автоматически переводится в v3-схему в памяти и проверяется по legacy fingerprint; если поведение действительно изменилось, загрузка завершается `ReplayMigrationRequired`. Проверенный старый replay можно материализовать в текущем формате через `digital_mind_core.persistence.upgrade_replay()`.

`--resume ... --steps N` добавляет N шагов к восстановленной истории. Параметры конфигурации берутся из сохранения, поэтому их нельзя переопределять вместе с `--resume`.

Внешние вызовы `mind.process()` и `mind.connect()` не включены в журнал симуляции. После таких вызовов сохранение replay явно отклоняется. Экспорт механизмов в JSON остаётся доступным. Импорт через `mind.load_mechanisms()` допускается до начала симуляции и учитывается при восстановлении.

## Проверки и результаты

```bash
python -m unittest discover -s tests -v
python tools/verify_legacy.py
python -m digital_mind_core compare --steps 640 --seeds 0 1 2 --report comparison.json
```

В этой сборке прошли **38 тестов проекта и 18 исходных тестовых скриптов v0.28**. Проверены регрессии, логика, подключение CSV, компиляция механизмов в L0, отложенный допуск и откат, перенос механизмов в новый экземпляр и восстановление состояния.

Проведены 12 запусков по 640 шагов: четыре режима на seed 0, 1, 2. Отключение и символического компонента, и синтеза воспроизводит прогнозные и reward-метрики прежней v0.1 на этих seed. Установочный wheel проверен вне дерева исходников: восстановление 640 шагов и продолжение до 648. Отдельный экземпляр с импортированным JSON-механизмом прошёл 96 шагов.

| Наблюдение | Результат |
| --- | --- |
| Полный запуск, seed 0 | 640 циклов символического ядра и 640 тактов L0 ARC |
| Автоматический синтез | Арбитр `min(history_cost, current_cost)` принят после 6 отложенных примеров |
| Исполнение арбитра, seed 0 | 155 вызовов через L0 Control IR |
| Изменение выбора арбитром, seed 0/1/2 | 0 случаев во всех трёх запусках |
| Средняя ошибка прогноза, полный режим | 0.005370809455192033 |
| Средняя ошибка без синтеза | Та же величина; поведение совпало с полным режимом |
| Средняя ошибка в режиме поведения v0.1 | 0.005373046071097902 |
| Допуск спектральной L0-модели в полный прогноз | Вес оставался 0 в этих экспериментах |

**Выигрыш от нового арбитра пока не показан.** Он синтезируется, сохраняется и исполняется, но не менял решения в исследованных симуляциях. Различия прогнозной ошибки между другими режимами малы, reward меняется неоднозначно, посещённые состояния различаются, а три seed недостаточны для вывода о росте способностей. Контролируемый тест отдельно подтверждает, что арбитр способен изменить выбор при подходящей паре стоимостей.

Свежие результаты находятся в `examples/test_results.txt`, `legacy_test_results.json`, `comparison.json`, `run_seed0.json`, `resumed_seed0.json` и `verification_summary.json`. `provenance.json` содержит хеши входных архивов. Отчёты внутри `legacy_v028/evaluation/` относятся к исходной ветке и не являются результатами новой сборки.
